# Creative Center — Центр творческих мастерских

HTML/CSS/vanilla JavaScript, без сборки и внешних зависимостей. Люди, адрес и события вымышлены. Формы работают локально, не отправляют данные, не оформляют запись и оплату.

## Три сценария запуска

### 1. Основной: GitHub Pages

Загрузите содержимое папки проекта в корень репозитория. В Settings → Pages выберите Deploy from a branch → main → / (root) → Save. Файл `.nojekyll` отключает обработку Jekyll. Откройте адрес, показанный GitHub после публикации; для текущего репозитория ожидается https://nsuem-projects.github.io/creative-center/ .

Python, Node.js и пакеты не нужны. Все пути статических ресурсов относительные, работают в подпапке репозитория. Учебные данные реально загружаются через HTTP из `assets/data/mock/`. Повторные fetch не объединяются. При отказе загрузки используются данные из `js/data.js` с сообщением в Console.

**Задержка расписания здесь — таймер JavaScript 3000 ms после загрузки JSON. Она НЕ является сетевым ожиданием и НЕ увеличивает Time запроса JSON на 3 секунды.** В Console это явно подписано.

### 2. Локально без установки программ

1. Полностью распакуйте ZIP; не открывайте HTML внутри архива.
2. Откройте `index.html` двойным щелчком в Chrome или Яндекс Браузере.
3. Редактируйте HTML/CSS/JS, например встроенным Блокнотом Windows, сохраняйте и обновляйте страницу.
4. DevTools → Network/Console открываются клавишей F12. Сравнивайте результаты до и после правок.

Через `file://` данные берутся из уже загруженного `js/data.js`: не нужны fetch JSON, модули, service worker и сервер. Каталог, фильтры, страницы по id, формы, сертификаты, карта и расписание сохраняют функциональность. Расписание использует таймер JS 3 секунды. Повторные вызовы данных фиксируются в Console и журнале, но **не создают HTTP-строк Network**.

Статические CSS/JS/изображения видны в Network как локальные загрузки. Transfer Size, HTTP-заголовки и кэширование могут отличаться от HTTP. Отсутствующие файлы дают ошибки загрузки, а не HTTP 404. Запрос отсутствующего JSON через fetch может блокироваться политикой file://; ошибка обработана. Точные тексты ошибок зависят от браузера. Сторонние ресурсы требуют интернета; при их отказе остаются локальные шрифты и карта.

### 3. Серверная практика (необязательная)

Для настоящего API и исследования сетевого ожидания нужен Python 3.9+. Установки пакетов нет. В папке проекта выполните `python server.py` (Windows: также `py server.py`). Откройте http://masterskaya.localhost:8000/ ; запасной адрес http://127.0.0.1:8000/ . Другой порт: `python server.py --port 8081`. Остановка: Ctrl+C.

Сервер отдаёт специальную версию `js/runtime-mode.js`, автоматически включающую реальные `/api/...`. `/api/schedule` действительно задерживает HTTP-ответ на 3 секунды в отдельном потоке. Дополнительный таймер JS в этом режиме не используется. Обычный статический HTTP-сервер включает автономный режим, как GitHub Pages.

## Какие задания доступны

| Задание | GitHub Pages / статический HTTP | Двойной щелчок file:// | server.py |
|---|---|---|---|
| Редактирование HTML/CSS/JS | После обновления файлов репозитория | Локально, без установки программ | Локально |
| Тяжёлые JS/CSS, сравнение размеров | Да, HTTP-ресурсы | Да, локальные ресурсы; метрики передачи отличаются | Да |
| Отсутствующие ресурсы | Настоящие HTTP 404 | Ошибки загрузки, без HTTP-статуса | Настоящие HTTP 404 |
| Сторонние домены | Да | Да, при доступной сети | Да |
| Повторные / многочисленные загрузки данных | Отдельные HTTP fetch статических JSON | Вызовы в памяти: Console, не Network | Отдельные HTTP API-запросы |
| Задержка расписания | JS 3 секунды, не TTFB | JS 3 секунды, не Network | Реальный TTFB около 3 секунд |
| Обработка отказа данных | JSON fetch → резервные данные | Обработка отклонённых вызовов в памяти | Отказ API → статический интерфейс |

## Проверка и диагностика

Network откройте до перезагрузки, включите Disable cache. Сортируйте Status, Size и Time, добавьте Domain через контекстное меню заголовков. Фильтр `mock/` выделяет автономные HTTP-данные, `/api/` — серверные. Запросы выполняются с cache: no-store, сервер также отдаёт Cache-Control: no-store.

В Console: `CreativeCenterTraining.mode` показывает режим; `CreativeCenterTraining.calls` — журнал вызовов с transport, ресурсом, ошибкой, fallback и jsDelayMs. Журнал отдельный для каждой страницы. `CreativeCenterTraining.read('/api/workshops/999').catch(console.error)` демонстрирует обработку неизвестного ID в file:// и серверном режиме; на статическом HTTP — HTTP 404 и отклонение резервного вызова. Это ручное задание, не автоматическая дополнительная ошибка.

Данные для редактора: js/data.js — интерфейс и резервный режим; assets/data/mock/*.json — статические HTTP-ответы. При изменении содержимого занятия обновляйте обе копии. Повторные вызовы намеренно не оптимизируются.

Страницы: index.html, workshops.html, workshop.html?id=1…10, teachers.html, teacher.html?id=1…3, schedule.html, certificates.html, blog.html, article.html?id=1…3, contacts.html.

Ограничения выполненной проверки описаны в VERIFICATION.md. Для серверного режима доступен verify.py (требует запущенный server.py на 8000). Установка Python/Node для двух автономных сценариев не требуется.
