## 1. Назначение и архитектура стенда

Учебный стенд предназначен для проведения практических и лабораторных работ по оптимизации фронтенда и веб-производительности. Комплекс развёрнут на едином сервере и включает:
1. **Эталонный сайт:** Неизменяемый образец, доступный по постоянному адресу `https://129-101-112-157.sslip.io/`. Служит образцом для сравнения метрик до и после оптимизации.
2. **25 независимых студенческих стендов:** Персональные публикации по адресам `https://129-101-112-157.sslip.io/students/student01/` … `https://129-101-112-157.sslip.io/students/student25/`.
3. **Единый учебный API:** Потокобезопасный серверный процесс (`creative-api.service`, порт 8000), обслуживающий все стенды. Обеспечивает реальные сетевые задержки и ответы на GET-запросы.
4. **Веб-панель управления преподавателя (Admin GUI):** Защищённый интерфейс по адресу `https://129-101-112-157.sslip.io/admin/` для контроля коммитов, проверки статусов и сброса любого стенда в 1 клик.

## 2. Подготовка к занятию (Lesson Preparation)

Перед началом лабораторной работы преподаватель выполняет следующую последовательность действий:

### Шаг 1. Проверка доступности инфраструктуры
1. Открыть в браузере эталонный сайт: `https://129-101-112-157.sslip.io/`. Убедиться в корректной загрузке главной страницы по HTTPS (замок в адресной строке активен).
2. Открыть страницу расписания `https://129-101-112-157.sslip.io/schedule.html`. В браузере (F12 → Network) проверить, что запрос `/api/schedule` отвечает со статусом 200 и задержкой ответа (TTFB) около 3 секунд.

### Шаг 2. Вход в веб-панель управления
1. Открыть адрес: `https://129-101-112-157.sslip.io/admin/`.
2. В окне HTTP Basic Auth ввести:
   * **Логин:** `admin`
   * **Пароль:** *[Пароль, установленный администратором сервера при первичной настройке]*
3. Убедиться, что на верхней панели отображаются зелёные индикаторы служб: `Nginx: active`, `API: active`, `GUI: active`.

### Шаг 3. Подготовка стендов к новой группе
1. Для сброса всех стендов к первоначальному эталонному состоянию нажать кнопку **«⚠️ Сбросить ВСЕ 25 стендов»** в верхней панели управления.
2. Подтвердить действие в диалоговом окне. Процедура сброса всех 25 стендов занимает около 1 секунды.
3. Убедиться, что на карточках всех 25 студентов статус сменился на `Синхронизирован с эталоном`.

### Шаг 4. Экспресс-тестирование стенда
1. В веб-панели нажать кнопку **«🧪 Проверить стенды»**.
2. Дождаться появления модального окна отчёта `cc-verify`. Убедиться, что все тесты (страницы, намеренные 404, эндпоинты API, задержка расписания 3 с, несжатые ассеты) имеют статус `[PASS]`.

### Шаг 5. Формирование ведомости группы
1. Составить список соответствия фамилий студентов и выделенных номеров (от 01 до 25):
   * Студент 01 → Ветка `student-01` → Стенд `https://129-101-112-157.sslip.io/students/student01/`

## 3. Проведение занятия (Lesson Delivery)

### Порядок выдачи задания студентам
1. Сообщить студентам адрес репозитория: `https://github.com/nsuem-projects/creative-center.git`.
2. Назначить каждому студенту его персональный номер (например, `student-04`).
3. Объяснить последовательность локального старта студента:
   ```bash
   git clone https://github.com/nsuem-projects/creative-center.git
   cd creative-center
   git checkout student-XX
   ```
4. Разъяснить студентам правила доставки:
   * На локальных компьютерах студентов **не требуется** установка Node.js, Python или баз данных.
   * Студенты редактируют файлы в любом текстовом редакторе (VS Code, Notepad++ и т.д.).
   * Для публикации правок выполняется:
     ```bash
     git add .
     git commit -m "Описание выполненной оптимизации"
     git push origin student-XX
     ```
   * Обновления публикуются на стенде студента автоматически в течение 1–20 секунд.

### Контроль работы в ходе занятия
1. На экране преподавателя открыта веб-панель `https://129-101-112-157.sslip.io/admin/`.
2. При отправке студентами коммитов панель автоматически обновляет данные каждые 15 секунд:
   * Отображается хэш коммита каждого студента.
   * Отображается текст сообщения коммита и время с момента отправки.
3. По кнопке **«Сайт ↗»** на карточке студента преподаватель может в один клик открыть текущий результат работы студента в новой вкладке.
4. При необходимости принудительного обновления нажать кнопку **«🔄 Git Sync»**.

## 5. Взаимодействие со студентами и правила безопасности (Student Interaction)

### Разрешённые действия студентов
* Редактирование файлов разметки (`*.html`), стилей (`css/*.css`), клиентских скриптов (`js/*.js`) и локальных данных (`assets/data/*.json`).
* Добавление оптимизированных изображений (`.webp`, `.svg`, `.png`, `.jpg`).
* Настройка клиентского кэширования через Web Storage API (`localStorage`, `sessionStorage`, `Cache API`).

### Запрещённые действия и механизмы автоматической защиты
* **Загрузка серверных скриптов:** Файлы `.php`, `.py`, `.sh`, `.cgi`, `.exe`, `.bat` автоматически удаляются сервером при деплое, а Nginx блокирует прямые запросы к ним с кодом `403 Forbidden`.
* **Загрузка файлов сверх квоты:** Введена квота на размер стенда — не более 50 МБ. При попытке залить тяжелые архивы деплой автоматически отклоняется.
* **Доступ к чужим стендам и эталону:** Студенты имеют права на пуш исключительно в закреплённые ветки `student-XX`. Эталонная ветка `main` защищена. Доступ по SSH студентам не предоставляется.

## 6. Оценка результатов и критерии приёмки (Assessment of Results)

При приёмке работы преподаватель оценивает результаты студента по трём группам критериев:

### 1. Критерии сетевой оптимизации (Network Performance)
* **Сокращение объёма передаваемых данных (Transfer Size):**
  * Размер загружаемых скриптов на странице мастер-классов снижен с ~2 МБ до минимально необходимого.
  * Размер стилей на странице журнала снижен с ~1.2 МБ.
* **Сокращение количества HTTP-запросов (Requests Count):**
  * На главной странице ликвидирован троекратный запрос `featured-workshops`.
  * На странице расписания исключены повторные запросы к `/api/workshops/*`.
* **Оптимизация отклика расписания (TTFB / Caching):**
  * При первом открытии расписания задержка 3 с обрабатывается визуальным индикатором (пользователь видит загрузку).
  * При повторном открытии страницы или переходе данные извлекаются мгновенно из клиентского кэша без сетевого ожидания.

### 2. Критерии устранения ошибок (Error-Free Network)
* Во вкладке Network и в Console браузера отсутствуют ошибки со статусом `404 Not Found`:
  * Нет битых запросов к `catalog-tags.json`.
  * Нет битых запросов к `journal-recommendations.js`.
  * Нет битых запросов к `entrance-evening.webp` и `map-theme.css`.

### 3. Критерии сохранения функциональности (UI Integrity)
* Интерактивные элементы продолжают работать корректно:
  * Мобильное меню открывается и закрывается.
  * Фильтр мастер-классов по категориям (Керамика, Живопись, Дерево) фильтрует карточки.
  * Кнопки масштабирования карты на странице контактов меняют масштаб.
  * Форма бронирования сертификатов функционирует штатно.

### Порядок проверки работы преподавателем
1. Открыть персональный URL студента в браузере Chrome или Яндекс Браузер.
2. Нажать **F12**, перейти во вкладку **Network**, выставить флаг **Disable cache**.
3. Перезагрузить страницу (`Ctrl+F5` или `Ctrl+R`) и зафиксировать сводные показатели в нижней строке вкладки Network (requests, transferred, resources, Finish time).
4. Сравнить полученные показатели с показателями эталонного сайта `https://129-101-112-157.sslip.io/`.
5. Проверить вкладку **Console** на предмет отсутствия необработанных исключений JavaScript.

## 7. Решение типовых проблем и нештатных ситуаций (Troubleshooting)

### Проблема 1. Студент запушил код, но на сайте отображается старая версия
1. **Проверка кэша браузера:** Убедиться, что студент нажал `Ctrl+F5` или включил чекбокс `Disable cache` во вкладке Network DevTools.
2. **Проверка статуса в веб-панели:** Открыть `/admin/` и проверить карточку студента. Если хэш коммита совпадает со свежим коммитом в GitHub — код доставлен на сервер.
3. **Принудительный запуск доставки:** Если коммит в GitHub есть, а на карточке старый хэш — нажать кнопку **«🔄 Git Sync»** в верхней панели для немедленного опроса репозитория.

### Проблема 2. Студент повредил верстку или скрипты и не может самостоятельно восстановить код
1. В веб-панели управления преподавателя (`/admin/`) найти карточку данного студента.
2. Нажать кнопку **«Сброс»** на карточке студента и подтвердить действие.
3. Стенд студента на сервере мгновенно (за 0.05 с) восстанавливается до чистого эталонного состояния.
4. Для сброса локального репозитория на компьютере студента передать ему команды:
   ```bash
   git fetch origin
   git reset --hard origin/main
   git push --force origin student-XX
   ```

### Проблема 3. Студент случайно переключился в чужую ветку или ветку main
1. На компьютере студента выполнить возврат в свою ветку:
   ```bash
   git checkout student-XX
   ```
2. Если студент внёс изменения не в свою ветку, перенести их или сбросить:
   ```bash
   git reset --hard HEAD
   git checkout student-XX
   ```

### Проблема 4. Стенд студента выдаёт ошибку 403 Forbidden
* **Причина:** Студент переименовал главный файл или пытается обратиться к запрещённым типам файлов (`.php`, `.py`, `.sh`).
* **Решение:** Проверить, что в корне каталога присутствует файл `index.html`. Удалить из репозитория исполняемые скрипты, сделать коммит и пуш.

### Проблема 5. В компьютерном классе временно недоступен внешний интернет
* Сервер и все 25 стендов размещены на независимом VPS в ЦОД Новосибирск и функционируют автономно.
* При недоступности CDN (Google Fonts, jsDelivr) сайт автоматически переключается на безопасные системные шрифты. Учебный процесс и выполнение заданий по оптимизации не прерываются.

## 8. Справочник инструментов администрирования

### 1. Веб-интерфейс преподавателя
* **URL:** `https://129-101-112-157.sslip.io/admin/`
* **Авторизация:** HTTP Basic Auth (`admin`)
* **Функции:** Мониторинг всех 25 стендов, сброс любого стенда в 1 клик, оптовый сброс 25 стендов, запуск верификации `cc-verify`, ручной запуск `Git Sync`.

### 2. Консольные команды VPS (SSH: `ssh root@129.101.112.157`)
* `cc-status` — отображение статуса всех 6 служб, потребления памяти/диска и времени последней доставки.
* `cc-reset <student_id>` — консольный сброс стенда студента (пример: `cc-reset student05` или `cc-reset 5`).
* `cc-reset-all` — консольный сброс всех 25 стендов к эталону.
* `cc-verify [URL]` — запуск автоматического проверочного набора тестов эталона или студента.
* `cc-backup` — создание резервной копии конфигурации и эталона (хранятся 7 последних копий в `/var/backups/creative-center/`).
* `htpasswd -B /etc/nginx/.htpasswd_admin admin` — смена пароля к веб-панели управления.
